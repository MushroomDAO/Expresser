# ADR-002 Expo SDK 版本策略

**状态**: 已采纳  
**日期**: 2026-05-01  
**决策人**: jhfnetboy  

---

## 背景

项目当前使用 Expo SDK 54（2025 年底最新稳定版）。  
开发过程中曾提出"建议 2 周后升级到新版"，用户对此动机和时间窗口的合理性提出了疑问。

## 决策

**不设固定升级窗口。按需升级，有明确收益或 bug 修复时才动。**

### 为何之前建议升级？

Expo SDK 54 发布初期，`expo-camera` 在部分 Android 设备（MIUI / ColorOS）上存在取景器旋转不同步的 bug，后续小版本（54.0.x）已修复。彼时建议等 2 周是为了让这批 patch 积累完。**现在（2026-05-01）SDK 54 已稳定，该 bug 已修，原升级理由已不成立。**

### 为何是"2 周"？

经验数字，无硬依据。SDK 大版本（如 55）正式稳定通常需要 4–8 周的 beta 周期，2 周只是"等第一批 patch"的直觉估算，不代表实际安全窗口。

## 升级原则

1. **非破坏性升级（patch）**：`expo-camera` / `expo-av` 等 patch 更新跟 `pnpm dlx expo install --fix` 处理，发现问题才动
2. **大版本升级（SDK 55+）**：等官方 migration guide 出来后专开分支评估，不在功能分支附带升级
3. **升级触发条件**：有明确修复的 bug、有需要的新 API、安全漏洞三选一
4. **不升级理由**："新版本出了"不是充分理由，避免无意义的维护成本

## 当前版本锁定

|---|---|---|
| expo | ~54.0.33 | 稳定，无迫切升级需要 |
| expo-camera | ~17.0.10 | 旋转 bug 已修 |
